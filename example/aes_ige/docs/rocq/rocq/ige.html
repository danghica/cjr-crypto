# Verified AES-IGE with proved algebraic properties

## Summary

Create `example/aes_ige` containing AES-128/192/256 encryption and decryption, verified IGE processing over separate buffers, extracted Cangjie, tests, benchmarks, and an offline report. Prove both implementation correctness and the key algebraic properties of the specification.

## Implementation and interfaces

- Model AES according to FIPS 197, using byte-valued integers, column-major state layout, concrete key expansion, and 10/12/14-round cipher loops.
- Add integer XOR and bitwise AND primitives to CJR, including semantics, WP rules, notation, extraction support, and correspondence tests. Use addition and masking for byte doubling.
- Implement the AES transformations and their inverses. Prove the S-box tables agree with the finite-field specification.
- Expose key expansion into a caller-owned 240-byte schedule buffer, returning the round count or zero for invalid key length. Provide block encryption/decryption and IGE encryption/decryption using reusable caller-owned workspace.
- Require disjoint input/output, IV, schedule, and workspace buffers. Preserve input and schedule. Reject invalid round counts and negative or non-block-aligned message lengths before modifying output or IV.
- Use a mutable 32-byte IV ordered as previous ciphertext followed by previous plaintext. Empty input succeeds and preserves the IV. Exclude padding, in-place operation, and bidirectional IGE.

## Specification and algebraic proofs

State and prove these properties independently of the embedded implementation, for every supported key size and valid input:

- **AES inverse laws:** `decrypt(k, encrypt(k, b)) = b` and `encrypt(k, decrypt(k, b)) = b`.
- **AES bijectivity:** derive injectivity and surjectivity of encryption and decryption from the inverse laws.
- **Transformation inverse laws:** prove both compositions for SubBytes/InvSubBytes, ShiftRows/InvShiftRows, and MixColumns/InvMixColumns. Prove applying AddRoundKey twice with the same round key is identity.
- **Byte-XOR laws:** prove associativity, commutativity, zero identity, self-cancellation, and byte-range closure, supporting AES and IGE cancellation arguments.
- **IGE inverse laws:** encryption followed by decryption, and decryption followed by encryption, recover the original message when both operations start from the same initial IV. Prove that the corresponding final IVs agree.
- **IGE bijectivity:** for a fixed key, initial IV, and block count, derive injectivity and surjectivity on messages of that length.
- **Length and range preservation:** AES preserves block size; IGE preserves message length; outputs and final IV remain byte-valued.
- **Empty-message identity:** both IGE directions return the empty message and unchanged IV.
- **Chunk composition:** processing `xs ++ ys` equals processing `xs`, then `ys` with the returned IV, for both encryption and decryption. Prove equality of concatenated outputs and final IV.

Define pure IGE operations as returning `(output, finalIV)` so the stateful laws are explicit. Round-trip laws reset to the original IV before the inverse operation; they do not reuse the mutated final IV.

## Implementation proofs and integration

- Separate the mathematical model, embedded programs, and proofs within the example.
- Prove Iris refinement contracts for helpers, key expansion, AES blocks, and complete IGE loops, including ownership, bounds, preservation, and IV updates.
- Derive implementation-level round-trip and chunk-composition contracts from refinement and the pure algebraic theorems.
- Use concrete AES throughout; introduce no admissions or assumed cipher correctness.
- Integrate build load paths, extraction, test/report dispatch, and the examples index. Audit the public correctness contracts and algebraic theorems with `Print Assumptions` and kernel checks.

## Validation and report

- Test AES known-answer vectors for every key size, OpenSSL IGE vectors, and independently generated AES-192/256 IGE fixtures with recorded provenance.
- Test both inverse compositions, chunk composition, empty and multi-block messages, high-bit bytes, final IV equality, rejected lengths, and memory preservation.
- Run full `make verify`, runtime regression suites, extraction checks, and report link checks. Prove machine-range bounds for AES arithmetic and indexing.
- Benchmark encryption/decryption at 16 bytes, 1 KiB, and 64 KiB for every key size; measure key expansion separately. Use three processes, seven samples per process, warm-up, and checked checksums.
- Produce the existing-style offline report with rendered specifications, dependency diagrams, proof narrative, test provenance, and benchmark charts. Give each algebraic law its statement, assumptions, proof explanation, and implementation consequence.
- State that the verified guarantees cover functional correctness and memory safety; constant-time behavior and cryptographic security proofs remain outside scope.

recursive function ige_encrypt:
    parameter(key, type(_ (inferred)))
    parameter(xs, type(list(block)))
    parameter(v, type(iv))
    type:
        product_type(list(block), iv)
    body:
        match RegularStyle:
            xs
            case:
                patterns(empty_list)
                tuple_with_tail_items(empty_list, items(v))
            case:
                patterns(cons(p, ps))
                let:
                    c
                    xor(encrypt(key, xor(p, fst(v))), snd(v))
                    match LetPatternStyle:
                        ige_encrypt(key, ps, tuple_with_tail_items(c, items(p)))
                        case:
                            patterns(tuple_with_tail_items(cs, items(w)))
                            tuple_with_tail_items(cons(c, cs), items(w))

Create `example/aes_ige` containing AES-128/192/256 encryption and decryption, verified IGE processing over separate buffers, extracted Cangjie, tests, benchmarks, and an offline report. Prove both implementation correctness and the key algebraic properties of the specification.

## Implementation and interfaces

- Model AES according to FIPS 197, using byte-valued integers, column-major state layout, concrete key expansion, and 10/12/14-round cipher loops.
- Add integer XOR and bitwise AND primitives to CJR, including semantics, WP rules, notation, extraction support, and correspondence tests. Use addition and masking for byte doubling.
- Implement the AES transformations and their inverses. Prove the S-box tables agree with the finite-field specification.
- Expose key expansion into a caller-owned 240-byte schedule buffer, returning the round count or zero for invalid key length. Provide block encryption/decryption and IGE encryption/decryption using reusable caller-owned workspace.
- Require disjoint input/output, IV, schedule, and workspace buffers. Preserve input and schedule. Reject invalid round counts and negative or non-block-aligned message lengths before modifying output or IV.
- Use a mutable 32-byte IV ordered as previous ciphertext followed by previous plaintext. Empty input succeeds and preserves the IV. Exclude padding, in-place operation, and bidirectional IGE.

## Specification and algebraic proofs

State and prove these properties independently of the embedded implementation, for every supported key size and valid input:

- **AES inverse laws:** `decrypt(k, encrypt(k, b)) = b` and `encrypt(k, decrypt(k, b)) = b`.
- **AES bijectivity:** derive injectivity and surjectivity of encryption and decryption from the inverse laws.
- **Transformation inverse laws:** prove both compositions for SubBytes/InvSubBytes, ShiftRows/InvShiftRows, and MixColumns/InvMixColumns. Prove applying AddRoundKey twice with the same round key is identity.
- **Byte-XOR laws:** prove associativity, commutativity, zero identity, self-cancellation, and byte-range closure, supporting AES and IGE cancellation arguments.
- **IGE inverse laws:** encryption followed by decryption, and decryption followed by encryption, recover the original message when both operations start from the same initial IV. Prove that the corresponding final IVs agree.
- **IGE bijectivity:** for a fixed key, initial IV, and block count, derive injectivity and surjectivity on messages of that length.
- **Length and range preservation:** AES preserves block size; IGE preserves message length; outputs and final IV remain byte-valued.
- **Empty-message identity:** both IGE directions return the empty message and unchanged IV.
- **Chunk composition:** processing `xs ++ ys` equals processing `xs`, then `ys` with the returned IV, for both encryption and decryption. Prove equality of concatenated outputs and final IV.

Define pure IGE operations as returning `(output, finalIV)` so the stateful laws are explicit. Round-trip laws reset to the original IV before the inverse operation; they do not reuse the mutated final IV.

## Implementation proofs and integration

- Separate the mathematical model, embedded programs, and proofs within the example.
- Prove Iris refinement contracts for helpers, key expansion, AES blocks, and complete IGE loops, including ownership, bounds, preservation, and IV updates.
- Derive implementation-level round-trip and chunk-composition contracts from refinement and the pure algebraic theorems.
- Use concrete AES throughout; introduce no admissions or assumed cipher correctness.
- Integrate build load paths, extraction, test/report dispatch, and the examples index. Audit the public correctness contracts and algebraic theorems with `Print Assumptions` and kernel checks.

## Validation and report

- Test AES known-answer vectors for every key size, OpenSSL IGE vectors, and independently generated AES-192/256 IGE fixtures with recorded provenance.
- Test both inverse compositions, chunk composition, empty and multi-block messages, high-bit bytes, final IV equality, rejected lengths, and memory preservation.
- Run full `make verify`, runtime regression suites, extraction checks, and report link checks. Prove machine-range bounds for AES arithmetic and indexing.
- Benchmark encryption/decryption at 16 bytes, 1 KiB, and 64 KiB for every key size; measure key expansion separately. Use three processes, seven samples per process, warm-up, and checked checksums.
- Produce the existing-style offline report with rendered specifications, dependency diagrams, proof narrative, test provenance, and benchmark charts. Give each algebraic law its statement, assumptions, proof explanation, and implementation consequence.
- State that the verified guarantees cover functional correctness and memory safety; constant-time behavior and cryptographic security proofs remain outside scope.
